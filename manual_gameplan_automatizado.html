1Introduccion

Que es el Game Plan Automatizado?

Un sistema que genera automaticamente el analisis pre-mercado de EduS Trader para los futuros ES, NQ, CL y GC, combinando datos de mercado en tiempo real con inteligencia artificial.

Que hace?

El sistema obtiene datos actualizados de ES, NQ, CL y GC via Yahoo Finance y lee tu Backtesting de Señales HUD V6. Construye un prompt estructurado con estos datos y el estado horario del mercado (Pre-Market, Abierto, etc.), lo envia a un modelo de IA (Groq, Gemini, Ollama, etc.), recibe el analisis en formato JSON, genera un HTML profesional con el Recomendador Cuantitativo incorporado, y lo publica automaticamente en edustrader.pages.dev via git push.

2Arquitectura

Como funciona el sistema

El flujo completo es una cadena de 4 pasos: desde los datos del mercado hasta la publicacion en la web.

1. Yahoo Finance → 2. Prompt + datos → 3. IA (Groq/Gemini/Ollama/etc) → 4. HTML + git push → edustrader.pages.dev
Tiempo total estimado: 15-30 segundos (dependiendo del proveedor IA)

Template HTML - Secciones

El HTML generado contiene 6 secciones principales, incluyendo la integracion con el HUD V6:

  1. PASO 01 — Sentimiento Global & Fundamentales: Barra de sentimiento, alertas principales, tabla de eventos economicos del dia.
  2. PASO 02 — Analisis Estructural: 4 tarjetas de zonas (ES, NQ, CL, GC) en grid 2x2 con resistencias, soportes y analisis Wyckoff.
  3. PASO 03 — Matriz de Escenarios: Barra de probabilidades y 3 escenarios (Alcista, Bajista, Lateral) con triggers, estrategia, targets para los 4 instrumentos e invalidacion.
  4. PASO 04 — Market Breadth: Grid de las 7 Magnificas (AAPL, MSFT, GOOGL, AMZN, NVDA, META, TSLA) y tabla de Top Movers del dia.
  5. PASO 05 — Estrategia Operativa: Setups (primario y secundario), horarios criticos y reglas de la mesa.
  6. PASO 06 — Recomendador de Señales HUD V6: Panel A cuantitativo (señales rankeadas por calidad en R + tamaño sugerido full/micro según el régimen VIX por mercado), Panel B narrativo de la IA, Panel C con la configuración recomendada del HUD y la estrategia, y Panel D con la recomendación para cuentas de fondeo (tamaño según el drawdown de la cuenta).

El sistema funciona en Windows con Python 3.11+. No requiere servidor ni cuenta paga (aunque algunos proveedores IA necesitan API key gratuita).

Requisitos del sistema

  • Windows 10/11
  • Python 3.11 o superior
  • Conexion a internet (para datos de mercado y API de IA)
  • Git instalado (para publicar en Cloudflare Pages)
  • Al menos 8GB de RAM recomendado (16GB si usas Ollama)

{

  "account_id": "APEX-2547813",   // nombre exacto de la cuenta en NT8
  "capital": 50000,
  "drawdown": 2000,        // el trailing DD que te quema la cuenta

El gameplan usa estas cuentas para el Panel D (qué señal y tamaño operar sin quemar el DD). El postmarket usa el account_id para medir tu drawdown real vs el límite. Una sola fuente para los dos sistemas.

5Backtesting

Actualización del Backtesting (HUD V6)

Cómo mantener actualizado el motor cuantitativo del Recomendador PASO 06. El pipeline tiene 3 pasos: pre-procesar el CSV, generar el mapa VIX→régimen, y generar el game plan.

Cómo modela el P&L (importante)

El pre-procesador calcula el resultado de cada operación con el modelo real de 2 contratos de tu estrategia AutoTrader V2: un contrato sale en T1 (parcial) y el otro es el runner que va a T2 o vuelve a BreakEven. En múltiplos de R: STOP ≈ −2R · BE ≈ +2R · T2 ≈ +5R. Antes se contaba 1 solo contrato, lo que subestimaba los ganadores y sesgaba el ranking de señales (las de muchos cierres BE parecían flojas cuando en realidad son ganadoras de +2R).

1. Exportar y ubicar el CSV

Genera el backtesting desde el HUD V6 en NinjaTrader (con las columnas MFE_R / MAE_R de excursión) y guárdalo como BT-senales-v5.csv dentro de la carpeta del sistema:

eduSTrader - Local Free\gameplan_system\BT-senales-v5.csv

Nota: el archivo conserva el nombre -v5 por compatibilidad, pero ya es data del HUD V6.

2. Pre-procesar el CSV
python preprocess_backtesting.py --csv "BT-senales-v5.csv"

Lee el CSV (cientos de MB), calcula el P&L de 2 contratos, las métricas de calidad y el Monte Carlo. Genera backtesting_summary.json. Parámetros útiles:

  • --capital 50000 — capital base para el Monte Carlo (por defecto $50.000).
  • --horizonte 200 — trades por campaña en el Monte Carlo (ver abajo).
  • --ruin-pct 0.20 — drawdown que define ruina.
Métricas nuevas en el resumen
MétricaQué es
expectancy_rExpectativa en R por trade (2 contratos) — independiente del tamaño del contrato. Es el criterio de ranking de calidad.
avg_mfe_r / avg_mae_rExcursión media a favor / en contra (en R). De las columnas MFE/MAE del HUD V6.
edge_ratioMFE/MAE — >1 = el precio va más a favor que en contra.
montecarlo_ruin_pctRiesgo de ruina con 2 contratos full.
montecarlo_ruin_microRiesgo de ruina con 2 micros (MNQ/MES = 1/10). Define el tamaño sugerido.

Monte Carlo por campaña: simula una campaña realista de 200 trades (no la serie histórica completa, que daba ruina casi siempre 100%). Mide el % de campañas que tocan un 20% de drawdown.

3. Generar el mapa VIX→régimen por mercado
python generar_vix_regimen_map.py

Solo es necesario re-ejecutarlo si cambian los stats VIX↔ATR. El HUD clasifica el régimen por ATR por mercado (modo AtrRange), así que el mismo VIX cae en distinto régimen según el mercado. Este script calibra los cortes VIX reales por mercado (ej. NQ ≈ 16.8/21.5/31.3/34.5, ES ≈ 18.9/25/30.9/37) en lugar del fijo 18/22/27/32. Genera vix_regimen_map.json.

4. Resultado

Quedan generados backtesting_summary.json (<1MB) y vix_regimen_map.json. A partir de aquí, cada Game Plan usa ambos para el PASO 06: rankea por calidad en R, sugiere el tamaño (full/micro) según tu capital, y elige el régimen correcto por mercado.

8Resultados

Que contiene el HTML generado

El Game Plan generado incluye analisis completo para los 4 futuros. Esto es lo que debe contener cada seccion.

Header

Logo "EduS Trader", fecha completa (ej: "MIÉRCOLES 10 DE JUNIO 2026"), la hora de generación dinámica (ej: "11:59 AM ET") acompañada del Badge de Estado de Mercado (PRE-MARKET, MERCADO ABIERTO, POST-MARKET, OVERNIGHT), y los precios de los instrumentos.

PASO 01 — Sentimiento Global

  • Barra de sentimiento: RISK-ON (verde), RISK-OFF (rojo) o MIXTO (beige)
  • Alerta principal: Bloque destacado con el shock o noticia mas importante del dia
  • Alerta secundaria: Contexto adicional relevante
  • Tabla de eventos: 5-7 filas con hora ET, nombre del dato, impacto (ALTO/MEDIO/BAJO), consenso y nota de liquidez

PASO 02 — Analisis Estructural

4 tarjetas en grid 2x2 (ES | NQ / CL | GC). Cada tarjeta contiene:

  • Nombre del instrumento y referencia de precio actual
  • Lista de resistencias con precios y tipo (HVN, LVN, POC)
  • Lista de soportes con precios y tipo
  • Nota de contexto Wyckoff / Market Profile especifica para ese instrumento

PASO 03 — Matriz de Escenarios

  • Barra de probabilidades: Visualizacion grafica de las 3 probabilidades (deben sumar 100%)
  • Escenarios (3): Alcista (verde), Bajista (rojo), Lateral (beige). Cada uno con:
    • Trigger / Condicion para que ocurra
    • Estrategia a seguir
    • Targets para ES, NQ, CL y GC (T1 y T2 para cada uno)
    • Invalidacion (que anularia el escenario)
    • Nota adicional de riesgo/recompensa

PASO 04 — Market Breadth

  • 7 Magnificas: Grid con las 7 (AAPL, MSFT, GOOGL, AMZN, NVDA, META, TSLA) mostrando precio, cambio % y sesgo (alcista/bajista/neutral)
  • Nota de sesgo: Analisis del comportamiento del grupo
  • Top Movers: Tabla con 3-5 tickers que mas se mueven en el pre-market, con cambio %, volumen relativo y causa

PASO 05 — Estrategia Operativa

  • Setup Primario: Nombre, descripcion detallada y parametros (Entry, Stop, Targets, R:R, Size)
  • Setup Secundario: Alternativa con menor probabilidad
  • Horarios Criticos: Tabla con zonas de alta volatilidad y accion recomendada (ej: "08:25-08:40 EVITAR")
  • Reglas de la Mesa: Lista de reglas para la sesion del dia

PASO 06 — Recomendador HUD V6

  • Panel A (Cuantitativo): Top señales por mercado y segmento (USA AM, Almuerzo, USA PM), rankeadas por calidad en R (expectancy_r). Cada una trae:
    • Tamaño sugerido — badge FULL (2 contratos) o MICRO (MNQ/MES), según si la ruina supera tu límite en tu capital.
    • Dirección (LONG/SHORT/AMBOS) y métricas: WinRate, R por trade, edge (MFE/MAE), ruina full/micro, y la expectativa en USD al tamaño sugerido.
    • Régimen por mercado: el mismo VIX se mapea al régimen correcto de cada mercado (NQ y ES tienen cortes distintos).
  • Panel B (IA — solo narrativa): El análisis narrativo de la IA, alimentado con los datos reales del Panel A y la configuración del Panel C (la IA ya no inventa su propia tabla ni su propia config). Explica en prosa las mejores señales del día, su tamaño (full/micro) y el régimen por mercado, sin contradecir los paneles cuantitativos. El Panel A (tabla) y el Panel C (config) son la autoridad; el Panel B los interpreta.
  • Panel C (Configuración recomendada): Parámetros sugeridos del HUD V6 (Kelt Stop %, RR1/RR2, LinReg Slope Threshold por mercado, modo de detección ATR, rankings de zona) y de la estrategia (TrailingATR, 2 contratos, capital, tamaño por mercado). Lo pendiente de validar va marcado con ⚠️.
  • Panel D (Cuentas de Fondeo) 🏦: Recomendación aparte para cuentas de prop firm / fondeo, donde la "ruina" es tocar el drawdown absoluto de la cuenta (no un % del capital). Por cada perfil de cuenta configurado (capital + drawdown) muestra, por mercado y segmento, la mejor señal operable y su tamaño (full/micro) que mantiene baja la probabilidad de quemar la cuenta, con el DD-ruina% (campañas de 200 trades que tocan el DD). Con contratos full el DD se toca casi siempre en cuentas chicas, así que el panel casi siempre recomienda micro (MNQ/MES); con más colchón de DD aparecen señales en full.

9Publicacion en Redes

Publicación automática en redes

Al terminar de generar el HTML, el sistema puede publicar un post con una tarjeta-imagen y un botón que enlaza al informe. Hoy está activo Telegram; X e Instagram quedan preparados para más adelante.

Qué publica

Un post con:

  • Tarjeta PNG 1080×1080 con la marca EduS (navy/dorado): sesgo del día, VIX y régimen por mercado, y las mejores señales (señal · dirección · tamaño full/micro). La arma generar_imagen_social.py con los datos reales del backtesting.
  • Texto con el resumen y el disclaimer educativo.
  • Botón inline "📊 Ver Game Plan" → base_url + nombre del archivo (el informe en la bitácora).

Todo corre dentro de un try/except: si la red falla, el HTML se genera igual. Solo se publica si redes.enabled y redes.telegram.enabled están en true.

Puesta a punto de Telegram (una sola vez)
  1. Creá un bot con @BotFather en Telegram → te da el token.
  2. Creá un canal (privado si querés controlar quién ve el contenido) y agregá el bot como Administrador con permiso "Publicar mensajes".
  3. Obtené el ID numérico del canal (empieza con -100…; los privados no tienen @username). Se saca con getUpdates tras publicar un mensaje, o reenviando un post a @getidsbot.
  4. Copiá secrets.example.json a secrets.json y pegá token y chat_id. Nunca en config.json ni en git.

⚠ Si el token alguna vez aparece en un chat o captura, regeneralo en @BotFather con /token.

Re-publicar a mano (respaldo)

Si el envío automático falló por un bug, publicar_hoy.py re-publica usando los datos reales del día y el último análisis guardado, sin tocar git ni la IA:

python publicar_hoy.py --dry                 # ver sin enviar
python publicar_hoy.py                        # gameplan + cierre de hoy
python publicar_hoy.py --only gameplan      # solo el gameplan
python publicar_hoy.py --date 20260616     # un dia puntual
10Troubleshooting

Solucion de problemas comunes

Problemas frecuentes y como resolverlos.

Error: API key no configurada
ERROR: API key para groq no configurada.

Solucion: Abre config.json y verifica que la clave api_key tenga el valor correcto. O configura la variable de entorno correspondiente (GROQ_API_KEY, GEMINI_API_KEY, etc.).

Error: modelo descontinuado
Error code: 400 - model_decommissioned

Solucion: Los proveedores actualizan sus modelos periodicamente. En config.json, cambia el model del proveedor por uno activo. Para Groq, consulta console.groq.com/docs/deprecations.

Error: Yahoo Finance no devuelve datos
Datos en vivo no disponibles. Usando datos offline de respaldo.

Solucion: Esto ocurre en fines de semana o cuando no hay conexion. En dias de mercado (lunes a viernes), los datos deberian funcionar. Verifica conexion a internet.

La IA no genera todos los campos esperados

Solucion: Prueba con otro proveedor. Groq (Llama 3.3 70B) y Gemini suelen dar los mejores resultados. Si el analisis viene incompleto, prueba el modo Manual (opcion 6) con ChatGPT o Claude web que suelen seguir mejor las instrucciones.

Ollama no responde
Error: Cannot connect to host localhost:11434

Solucion: Asegurate de que Ollama esta instalado y corriendo. Abre PowerShell y ejecuta ollama list. Si no aparece, inicia Ollama desde el menu de inicio. Luego ollama pull llama3.1 si no lo has descargado.

Git push falla
⚠ Error en git push

Solucion: Asegurate de que el repositorio tiene un remote configurado. Ejecuta git remote -v dentro del repo. Si no hay remote, agrega: git remote add origin <url>. Verifica tambien que las credenciales de GitHub esten configuradas.

Telegram: 404 Not Found / no publica
[redes] Telegram: faltan token/chat_id
[redes] Telegram: ✗ error → 404 Not Found

Solucion: 1) Revisá que secrets.json tenga token y chat_id (el -100… del canal). 2) En la URL del bot NO se escriben los signos < > del placeholder. 3) El bot debe ser Administrador del canal con permiso de publicar. 4) Probá primero con --dry-redes y, si el post se ve bien, sacá el flag.

Pro tip: atajo de un solo click

Usa el archivo INICIAR_GAMEPLAN_AUTO.bat para ejecutar todo automaticamente sin abrir PowerShell:

  1. Navega a eduSTrader - Local Free/gameplan_system/
  2. Haz doble click en INICIAR_GAMEPLAN_AUTO.bat
  3. El sistema: instala dependencias → pide elegir metodo → genera → publica

Para ejecucion completamente desatendida (programable con Windows Task Scheduler), necesitas configurar ai.default_provider en config.json y usar:

python generar_gameplan.py --auto

Esto salta el menu y usa el proveedor por defecto.
